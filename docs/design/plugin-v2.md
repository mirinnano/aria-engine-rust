# プラグイン API v2 と責任の分担（設計案）

この文書は、プラグイン API v2 の設計案である。
v2 では、エンジンも PAK も更新せずにプラグインだけを差し替えられる。
プラグインは、台本から呼べる命令、VM の出来事への介入、画面の入力方針、描画までを受け持てる。
ゲームは、所定のフォルダにある署名済みのプラグインを、列挙せずに読み込む。
後半では、Aria の台本、プラグイン、表示パッケージ（TypeScript と CSS）のあいだで何をどこに書くかを定める。

## 責任の分担

v2 で書ける範囲が広がると、同じことを台本でもプラグインでも表示パッケージでも書けるようになる。
そこで、置き場所を次の規則で決める。
規則の基準は、その情報が物語の意味を持つか、見た目だけを決めるかである。

| 層 | 書くもの | 書かないもの |
|---|---|---|
| Aria の台本 | 本文、話者、順序、分岐、待ち時間、演出の意図（`stage`、`camera`、遷移）、背景と音の素材、章や引用などの物語の資料 | 座標、色、字体、レイアウト |
| プラグイン（Wasm） | 複数の作品で使い回す振る舞い、台本の文法では書きにくい計算、物語状態に基づく本文や選択肢の加工、独自画面の入力方針と描画 | 個々の作品の本文、作品固有の資料 |
| 表示パッケージ（TS/CSS） | 見た目（レイアウト、字体、配色、動きの曲線）、`stage` の名前に対応する写真や色、操作の割り当て、アクセシビリティ、UI の文言 | 物語の資料、物語上の意味を持つ時間、章見出しや背景色から物語状態を推定する表 |

待ち時間は物語の一部として台本に書く。
読者の設定（文字速度、動きを抑える）で変わる時間だけを表示パッケージが決める。
表示パッケージが本文の位置を知る必要があるときは、表示モデルの値（`stage`、章の宣言、話者 ID）を読む。
背景色や見出しの文字列から物語状態を推定しない。推定は、台本を書き換えたときに黙って外れるからだ。

## プラグインの形

### ファイル

プラグインは、拡張子 `.ariaplugin` の一つのファイルである。
中身は、マニフェスト（JSON）、Wasm の本体、省略できる Web 用 UI モジュール（ES module）、省略できる素材で、全体に発行者が Ed25519 で署名する。
署名鍵は PAK と同じ発行者鍵の系統を使い、検証鍵 ID は作品の `aria.toml` に書く。

```toml
[plugins]
verification_keys = ["publisher"]
require = { "jp.ponkotsu.hesphoros.story" = "^1" }
```

`require` は、作品が動くために必要なプラグインと、その互換範囲（semver）を宣言する。
ファイル名やパスは書かない。

### 置き場所と読み込み

起動時に、ゲームは次の二つのフォルダにある `.ariaplugin` をすべて読み、署名を検証する。

1. インストール先の `plugins/`（配布物に同梱したもの）
2. ユーザーデータの `plugins/`（あとから配った更新）

同じ ID のプラグインが複数あれば、署名が正しく、`require` の範囲に入るもののうち、版がいちばん新しいものを使う。
更新をユーザーデータに置くのは、macOS ではアプリの中身を書き換えるとコード署名が壊れて起動できなくなるからだ。
Web 版では、サイトの `plugins/index.json` が一覧を持ち、Service Worker が他の資源と同じ規則で更新する。

署名が合わない、鍵 ID を作品が許していない、`require` を満たすものがない、のいずれかに当たると、そのファイルは読み込まず、理由を診断に出す。
必須のプラグインが一つも満たされない場合は、ゲームを始めない。

### 権限

マニフェストは、使う権限を宣言する。

| 権限 | できること |
|---|---|
| `commands` | 台本から呼べる命令を定義する |
| `hooks` | VM の出来事に介入する |
| `routes` | 独自画面の入力方針を登録する（v1 と同じ） |
| `state` | 変数・フラグを読み書きし、プラグイン自身の状態を保存に入れる |
| `render` | 描画命令を出す。Web では UI モジュールを読み込ませる |

宣言していない権限のホスト関数は、Wasm から呼べない。
署名した発行者だけがプラグインを配れるので、権限は作品への許可ではなく、レビューのための表示である。

## 台本からの呼び出し（`commands`）

```aria
let total = hesphoros::score(days, trust);
hesphoros::mark_visited("shore");
```

命令は `プラグインの名前空間::命令名` で呼ぶ。
コンパイラは、ビルド時に見つかったプラグインのマニフェストから引数と戻り値の型を読み、呼び出しを検査する。
バイトコードには名前で記録し、実行時に読み込んだプラグインへ解決する。
プラグインを更新して命令の型が変わった場合は、読み込み時に照合して、合わない呼び出しを持つ作品は始めない。

引数と戻り値は、Aria の値（`Int`、`Bool`、`String`）だけを受け渡す。
命令の実行は VM の一歩の中で終わり、時計・乱数・入出力を使えないので、Native と Web で同じ結果になる。
乱数が要る命令には、VM が保存と再生の対象にしている乱数列をホスト関数で渡す。

## VM の出来事への介入（`hooks`）

| 出来事 | プラグインができること |
|---|---|
| `text` | 表示する一行の本文・話者を書き換える |
| `choices` | 選択肢を足す、除く、並べ替える、ラベルを変える |
| `scene_enter` / `scene_exit` | 状態を読み書きする |
| `save` / `load` | プラグイン自身の状態を書き出す、読み込む |

介入の結果は表示モデルに入る前に確定し、既読の判定と保存の行キーには加工前の行を使う。
介入で本文を書き換えても、改稿時の位置合わせと既読がずれないようにするためだ。
同じ出来事に複数のプラグインが介入する場合は、プラグイン ID の辞書順に適用する。

## 描画（`render`）

描画は二段で受け持つ。

- 描画命令：プラグインは、独自画面か専用の重ね合わせ層に、エンジンの描画命令（画像、矩形、文字）を出す。Native も Web も同じ命令を描くので、どちらでも動く。
- Web 用 UI モジュール：Web 版とデスクトップ版（WebView）では、プラグインに同梱した ES module を表示パッケージが読み込み、独自画面の描画を任せる。モジュールは表示モデルを受け取り、意図（intent）を返す。物語状態を直接は書き換えない。

UI モジュールは表示パッケージと同じ権限で WebView 内に動くので、署名の検証を通ったものだけを読み込む。

## 保存の互換

v1 では、プラグインの中身が一ビットでも変わると、以前の保存を開けなかった。
v2 では、保存にプラグイン ID と、プラグインが宣言する状態の版（`state_version`、整数）を記録する。

- 状態の版が同じなら、そのまま読み込む。
- 版が上がっていれば、プラグインの `migrate(from_version, bytes)` で変換してから読み込む。
- 変換できない場合、または必須のプラグインがない場合だけ、読み込みを拒否する。

命令の型と出来事の介入は、保存の中身には入らない。
そのため、命令の中身や介入の規則を直す更新では、`state_version` を上げなくてよい。

## 実装の順序

1. `.ariaplugin` の形式、署名、二つのフォルダからの読み込み、`require` の照合、保存の `state_version`
2. `commands` と `state`（コンパイラの型検査、名前による解決）
3. `hooks`
4. `render`（描画命令、Web 用 UI モジュール）
5. HesPhoros の表示パッケージから、物語の資料と物語上の時間を台本へ移す

v1 のプラグイン（Wasm を PAK に入れ、`aria.toml` の `runtime.plugins` に列挙する形）は、1 の段階で読み込めなくなる。
作品側の移行は、Wasm を `.ariaplugin` に包み直し、`[plugins] require` を書くことで済む。
