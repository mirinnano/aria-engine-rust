# 台本と表示パッケージの分担

Aria の作品は、台本（`.aria`）、プラグイン（Wasm）、表示パッケージ（作品が持つ React などの UI）の三つで組み立てる。
同じことをどれにも書けるので、置き場所を次の規則で決める。
規則の基準は、その情報が物語の意味を持つか、見た目だけを決めるかである。

| 置き場所 | 書くもの | 書かないもの |
|---|---|---|
| 台本 | 本文、話者、順序、分岐、待ち時間、演出の意図（`stage`、`camera`、遷移）、背景と音の素材、章・資料・CG の宣言 | 座標、色、字体、レイアウト |
| プラグイン | 作品をまたいで使い回す振る舞い、台本の文法では書きにくい計算、物語状態に基づく本文や選択肢の加工、独自画面の入力方針と描画 | 個々の作品の本文や資料 |
| 表示パッケージ | レイアウト、字体、配色、動きの曲線、`stage` の名前に対応する写真や色、操作の割り当て、アクセシビリティ、UI の文言 | 物語の資料、物語上の意味を持つ時間、章見出しや背景色から物語状態を推定する表 |

待ち時間は物語の一部なので、台本の `wait` が決める。
表示パッケージが決めてよい時間は、読者の設定（文字の速さ、動きを抑える）で変わるものだけである。
表示パッケージが物語の位置を知りたいときは、表示モデルの値（`stage`、章の宣言、話者 ID）を読む。
背景色や見出しの文字列から物語状態を推定しないのは、台本を書き換えたときに推定が黙って外れるからである。

## 表示モデル

VM は一歩ごとに、表示パッケージへ表示モデル（`UiViewModel`、JSON）を渡す。
表示パッケージは表示モデルを描き、読者の操作を意図（`UiIntent`）として VM に返す。
表示モデルの版は `UI_VIEW_MODEL_SCHEMA` で、TypeScript の型は `ui/packages/aria-ui-sdk` にある。

主な項目は次のとおりである。

| 項目 | 中身 |
|---|---|
| `route`、`route_stack` | いまの画面と、その下に重なっている画面 |
| `dialogue` | 本文、話者、話者 ID、ルビ・傍点の範囲、ページ送りの状態。`prose` の `+` で続く行は、同じ `page_id` の本文に追記され、`text` はそれまでに表示した部分から伸び続ける |
| `choices`、`actions` | 選べる選択肢と、押せる操作 |
| `stage`、`camera` | 背景の意味と、カメラの目標 |
| `timed_hold_remaining_ms`、`timed_hold_total_ms` | 台本が決めた待ちの残りと全体。進み具合を描くときに使う |
| `chapters`、`gallery`、`collections` | 章、CG、資料の宣言と、その解放状態 |
| `story_surface`、`route_plugin` | 独自画面の入力方針と、その画面を登録したプラグイン |
| `settings`、`backlog`、`confirmation` | 設定、読んだ本文の履歴、確認待ちの操作 |
| `system_revision` | システムデータ（周回をまたぐフラグ、既読、章と CG の解放、設定）が変わるたびに増える数 |

画面の描画は、表示モデルとは別に `scene`（描画命令の列）でも渡る。
写真や単色の背景、表示資源、プラグインの描画層はここに入る。

意図には、操作の実行（`Activate`）、画面を開く・閉じる（`OpenRoute`、`Dismiss`）、設定の変更、スクロールがある。
VM は、知らない画面名や、存在しない選択肢を指す意図をエラーとして拒否する。

## ホストの受け持ち

ホスト（Web 版のページ、デスクトップ版の殻）は、VM と表示パッケージのあいだで、保存と素材の読み込みを受け持つ。
保存は、保存枠と、作品ごとに一つのシステムデータに分けて書く（[言語仕様の「保存」](aria.md#保存)）。

1. 起動したら、保存してあるシステムデータを VM に渡してから、最初の `step` を呼ぶ。
2. 表示モデルの `system_revision` が前回と変わったら、VM からシステムデータを取り出して書き出す。
3. 保存枠を読み込むときは、保存枠をそのまま VM に渡す。システムデータとの合わせ方は VM が決める。

システムデータを書き出さないホストでは、周回をまたぐフラグ、既読、解放、設定が、アプリを閉じると失われる。
