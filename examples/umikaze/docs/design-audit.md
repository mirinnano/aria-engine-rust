# デザイン監査 2026-10-13

Web版（1280×720、390×844）を Playwright で起動し、タイトル、CONFIG、LOAD、CHAPTERS、日付カード、本文、メニュー、LOG を撮影して確認した。
UI文言は `ui/src/copy.ts` と `App.tsx` の直書きを読み、日本語は LLM 由来の空句・翻訳調・擬人化を基準に点検した。

## 1. 演出を Aria から指定できなかった問題

### 何が起きていたか

単色の背景がどの場面を表すかを、React 側が RGB 値から推定していた。
`background asset("#284b59")` を書くと、表示側の表で `40,75,89` が `school` に対応しているため、夏の車窓の写真が出る。
作者がこの対応を知るには TypeScript の表を読むしかなく、色を一つ変えるだけで写真が黙って `tide` に戻る。
日付カードの天気も、選択肢ラベルの先頭行（`DAY 1` など）を見出しとして表から引いていた。

### 何を変えたか

`stage <名前>;` を Aria の文として追加した。

```aria
background asset("#6d706f") with fade(260ms);
stage stillness;
```

- 名前は英小文字・数字・`-`・`_` だけを受理する。`#264450` を書くとコンパイルエラーになるので、色の指定が台本へ戻ってくることはない。
- 値は次の `background` で消える。日付カードで書いた `departure` が、後の灰色の statement 画面へ残らないようにするためである。
- 値は VM の状態と保存に含まれ、UI view model の `stage` として渡る（view model schema 8 → 9）。
- React は「写真素材のパス → `stage` → 旧RGB表」の順で場面を決める。RGB表は、`stage` を持たない保存から再開した直後のためだけに残してある。
- `import-novel --presentation umikaze` も同じ行を出力する。検証器は `stage` を時間の拍として数えない。

海風の台本には 37 箇所の `stage` を入れた。いずれも、従来 RGB 表が推定していた値と同じ名前なので、画面の見た目は変わらない。

| 用途 | 使える名前 |
|---|---|
| 単色の背景 | `blackout` `stillness` `whiteout` `tide` `school` `blue` `city`（ほか `ui/src/scene-assets.*.ts` の `sceneAssetByTone` のキー） |
| 日付カード | `ward` `departure` `rain` `rail` `shore` `clear` `island` `harbor` `north` `terminus` `spring` |

### 残っている課題

- 名前の綴りを間違えても、コンパイラは気付かない。表示側の語彙を `aria.toml` に宣言させ、`aria check` で照合するのが次の段階になる。
- 章のメタデータ（命題、日付、紹介文）は `index.aria`、`demo.aria`、各章の日付カード、`chapter-preview.*.ts` の4箇所に同じ文を持っている。さらに `import-novel` の表は3行形式のままで、現行の5行形式の章ファイルを再生成できない。README の「章ファイルは生成物」という記述は、現状では成り立っていない。メタデータを一箇所（`aria.toml` か章ごとの宣言）に寄せる設計が要る。

## 2. UI 文言

### 「記録」が四つの意味を兼ねていた

日本語版では「記録」が、物語そのもの（記録をはじめる）、セーブデータ（記録を開く）、本文画面（記録へ戻る）、起動エラーの見出しを同時に指していた。
「記録をはじめる」と「記録を開く」が並ぶと、どちらが新しく読みはじめる操作か判別できない。
作品名に関わる「記録をはじめる」だけを残し、セーブ関係は「保存」「位置」「スロット」に寄せた。

| キー | 旧 | 新 | 理由 |
|---|---|---|---|
| saveSlot / loadSlot | 記録 1 に残す / 記録 1 を開く | スロット 1 に保存 / スロット 1 から読む | 上記の多義を解消 |
| saveLead | いま読んでいる場所を、ひとつの記録として残します。 | いま読んでいる位置を保存します。 | 一文で足りる |
| loadLead | 残しておいた記録から、読む場所へ戻ります。 | 保存した位置から読み直します。 | 同上 |
| writeRecord | この瞬間を残す | ここに保存 | 「瞬間」は保存される内容と合わない |
| emptyRecord | この記録には保存されていません。 | 空き | 主語が不明で、10行並ぶと読む負担が大きい |
| returnToReading | 記録へ戻る | 物語へ戻る | 多義の解消 |
| menuDescription.resume | 読書画面へ戻る | 読んでいた場面へ戻る | 「読書画面」は内部の呼び名 |
| menuDescription.save / load | 現在位置を記録する / 保存した記録を開く | いまの位置を保存する / 保存した位置から読む | 多義の解消 |
| menuDescription.extra | 解放済みの記憶を見る | これまでに見た場面を見る | ゲーム用語を避ける |
| memory | 記憶の断片 01 | 場面 01 | 装飾語を外す |
| locked | まだ届かない記録 | まだ読んでいない章 | 「届かない」は何が何に届かないのか特定できない比喩 |
| noEntries（LOG） | まだ読み返せる記録はありません。 | まだ読んだ文章はありません。 | LOG とギャラリーで同じ文を使っていたので分けた |
| noGallery（新設） | — | まだ見られる場面はありません。 | 同上 |
| lockedMemory（新設） | — | 未開放 | ギャラリーに「まだ読んでいない章」は不適 |
| confirmQuit | アプリケーションを終了しますか？ | 海風を終了しますか？ | 作品名で呼ぶ |
| confirmResume | このページから読み直しますか？ 先の本文と選択の記録は新しい分岐になります。 | この文から読み直しますか？ ここより先の進行と選択は、やり直しになります。 | 「新しい分岐になる」では何が失われるかが分からない |
| ok / ng | OK / NG | 終了する・ここから読む・タイトルへ戻る / やめる | ボタンが結果を名乗る。「NG」は俗語 |
| startupIssue | 記録を開けませんでした。更新して、もう一度開きます。 | ゲームデータを読み込めませんでした。 | 「更新して開きます」は誰がするのか曖昧。操作はボタンに任せる |
| reopenRecord | 更新して開き直す | 再読み込み | 同上 |
| openingRecord | 記録を開いています | 読み込んでいます | 待機表示は平易に |
| demoLead | この先の記録は、まだ閉じられています。 | DAY 5 以降は、この体験版に含まれていません。 | 受け身の比喩をやめ、事実を書く |
| reading（aria-label） | 読書中 | 本文 | スクリーンリーダーが読み上げる領域名 |
| readingControls / systemSection | 読む / 記録 | 文章 / 動作 | CONFIG の見出し。SYSTEM 欄に「記録」は内容と合わない |

英語・中国語は、新設キーの訳と、英語の `emptyRecord`、`startupIssue`、`reopenRecord` だけを直した。中国語の既存文は今回見ていない。

## 3. 画面ごとの所見

### 修正したもの

- **CHAPTERS の一覧**：命題が `…うちにあ…` のように文の途中で切れていた。省略をやめて折り返し、`word-break: auto-phrase` と `text-wrap: balance` で文節の境目で折るようにした。左の大きな見出しと日付カードの見出しにも同じ規則を当て、「ある。」だけが次の行に落ちる状態を解消した。
- **LOAD の空きスロット**：空きの行に「記録を開く」という押せない操作名が出ていた。操作名を消し、説明を「空き」にした。
- **オーバーレイの背景**：CONFIG、LOAD、LOG、CHAPTERS がすべて昼の高架下の写真を使い、タイトルや本文と色調が揃っていなかった。開いた元の画面を引き継ぐようにした。タイトルから開いたときはタイトルの夜の写真と紺・赤紫の色調、読書中に開いたときはその場面の写真を暗くぼかしたものを使う。
- **RMenu**：左上の幅24remの枠に10項目が詰まっていた。画面の高さいっぱいの縦列にし、「再開／読み方／保存／付録／終了」の5群を余白で分けた。説明文は項目の右に出すので、フォーカスを移しても列が動かない。押せる範囲は44pxを保っている。
- **起動画面**：ぽんこつソフトのロゴと『HesPhoros』のロゴを、黒地に順にフェードイン・アウトさせる。キーかクリックで次へ進み、その入力はタイトルへ届かない。ロゴはサークルの公式サイトから取得した。

### 直していないもの（推奨順）

1. **タイトルの引用群が互いに重なっている。** 1280×720 で上部と右側の引用が三、四行重なり、どの文も読めない。45の出典付き引用を見せる意図と、判読できない状態が矛盾している。重なりを許すのは断片（360個）だけにし、出典付き引用は互いに避けて配置することを勧める。タイトルの意匠そのものに関わるので、今回は手を入れていない。
2. **LOAD の9行目以降が画面下で切れている。** 1280×720 では9行目が途中で切れ、スクロールできることを示すものがない。
3. **小さな英字ラベル。** 日付カードの `PROLOGUE` などの見出しは 1280px 幅で約12px、`BEGIN` は約13pxで、字間が広く、背景の写真と重なると読みにくい。README の「14px 下限」は日付には守られているが、これらの英字ラベルは対象外になっている。
4. **日付カードの数字が二重に出ている。** 左に小さな `P`、右端に切れた大きな `P` があり、左の `P` は見出しから離れて浮いている。どちらか一方でよい。
5. **LOG の行間。** 1行の本文に約104pxの行を取っており、1画面に5件しか入らない。
6. **出典付き引用の重複。** 「倫理と美学とは一つである。」が『草稿 1914–1916』と『論考』6.421 の二つの出典で2回入っている。どちらも原典にある文だが、画面上は同じ文が2回出る。
