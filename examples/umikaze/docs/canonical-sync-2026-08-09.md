## Chapter progression contract

The generated selector registers `canonical_chapter_00` through
`canonical_chapter_10` with `chapter <id> progress 0`, then initially unlocks
only the prologue at progress 1. Chapter entries no longer self-unlock. Every
Day 0–9 story scene completes its own progress, persists
`canonical_chapter_NN_completed=true`, and unlocks exactly the next chapter;
Day 10 only completes itself.

Core now keeps chapter registration monotonic, so selector revisits retain
completion and unlock state. The generated contract is exercised by the sample
test: a staged execution of Day 0's real completion tail unlocks Day 1.

The content-limited demo registers only Day 0–4 and initially unlocks only
the prologue. It uses a non-verbal `umikaze_demo_edition` flag so canonical
Day 4 completes itself without registering the unavailable Day 5; replay
therefore remains a five-chapter selector. Its build namespace is
`umikaze-demo-v2`. The current CLI content-edition override intentionally
emits no legacy purge list, so a demo bundle records an empty
`legacy_save_namespaces` list rather than claiming a purge that its build API
cannot express.
